# Releasing

Releases are built entirely by `.github/workflows/release.yml` when a `v*` tag is pushed.

## One-time setup (repository secrets)

| Secret | Required | Purpose |
| --- | --- | --- |
| `MINISIGN_SECRET_KEY` | yes | Contents of the minisign secret key used to sign update packages. Its public half is `packaging/minisign.pub` and is embedded in the app (`crates/vanta-app/src/app/update.rs`). |
| `VANTA_MSA_CLIENT_ID` | for sign-in | Azure application ID (see README → Microsoft sign-in setup). Builds without it cannot sign in. |
| `WINDOWS_CERT_PFX_BASE64` | optional | Base64 of a code signing certificate (`.pfx`). When missing, Windows signing is skipped. |
| `WINDOWS_CERT_PASSWORD` | optional | Password of that certificate. |

Never commit any of these. If the minisign key is ever lost, generate a new pair
(`rsign generate -W` or `minisign -G -W`), replace `packaging/minisign.pub` and
`PUBLIC_KEY`, and ship one release that existing installs will not be able to
auto-update to (users download it manually once).

## Cutting a release

1. Update `version` in the root `Cargo.toml` (`[workspace.package]`) and the
   `<releases>` entry in `packaging/linux/xyz.getvanta.Vanta.metainfo.xml`.
2. Update `CHANGELOG.md`: `git cliff --unreleased --tag vX.Y.Z --prepend CHANGELOG.md`.
3. Commit: `chore(release): vX.Y.Z`.
4. Tag and push: `git tag vX.Y.Z && git push origin main vX.Y.Z`.
5. The workflow builds Windows and Linux in parallel, then the Arch package,
   then publishes the GitHub Release with:
   - `Vanta-Setup-X.Y.Z.exe`, `Vanta-X.Y.Z-portable.exe`
   - `Vanta-X.Y.Z-x86_64.AppImage`, `vanta_X.Y.Z_amd64.deb`,
     `vanta-X.Y.Z-x86_64.pkg.tar.zst`, `vanta-X.Y.Z-x86_64-linux.tar.gz`
   - a `.minisig` for every file and `SHA256SUMS.txt`
   - release notes generated by git-cliff from Conventional Commits
6. AUR: update `pkgver` and `sha256sums` in `packaging/aur/PKGBUILD`
   (`updpkgsums`), regenerate `.SRCINFO` (`makepkg --printsrcinfo > .SRCINFO`)
   and push both to `ssh://aur@aur.archlinux.org/vanta-bin.git`.

To rebuild an existing tag, run the workflow manually with the tag name.

## Website

The site in `web/` is hosted on Cloudflare Pages (project `getvanta`, domain
getvanta.xyz). After changing it, deploy with:

```sh
npx wrangler pages deploy --branch main
```

`wrangler.jsonc` points wrangler at `web/`. Log in once with `npx wrangler login`.
